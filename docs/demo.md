# EchoCrypt — Demo plan (Kiroween 2026, Resurrection)

Recorded video, **under 3:00**, public on YouTube. No copyrighted music or sounds:
the modem handshake is generated by us (`scripts/modem.wav` synthesised from tones).

## Ground rules for the video

1. **Everything shown is real.** Long agent runs are recorded live, then shown with
   `echocrypt replay --speed N`, which re-renders the real event log faster.
   A corner badge says `REPLAY ×20 — real log <run-id>`.
2. **Hard moments are triggered, not faked.** Crashes and cheating attempts come from demo
   tools (`chaos`, `rogue`) that use the same public API as any agent.
3. **Show the rule, then the rule firing.** For each guarantee: 2 s on the steering / hook
   file, then the terminal refusing.
4. One idea per scene. Captions carry the BBS → ADE mapping.

## Likely judge questions

| Question | Short answer |
|---|---|
| Is the replay faked? | No. Same event log, re-rendered faster; run id shown on screen. |
| Why a BBS and not a dashboard? | Locks, hand-off packets, moderation and a sysop already existed there; we map each to a real ADE problem. |
| What stops an agent cheating? | Server rules, Kiro hooks before the call, and PBT proving no path to `done` without review. |
| Does it work without Kiro Crew? | Yes, `KiroCliRunner`; any Kiro surface can dial in over MCP. |
| How does a new agent avoid repeating work? | QWK packet built from the log; `tried` is never dropped; ACK required. |
